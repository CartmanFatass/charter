# Delegation model as shipped in charter 0.44.0 — every persona is affecte

_2026-08-18 23:14 · persistent_

Delegation model as shipped in charter 0.44.0 — every persona is affected, whether acting or being routed to. A persona declares its OWN outbound posture: 'routing: off|advise|require' (absent = off) and 'routes-to: a, b' (prioritises the roster, never restricts it). There is NO plane-level routing setting and never will be: the level is read from the ONE acting persona in a session, so a floor would reach personas that never asked for it. A new plane gets its default from the generated front-door persona's frontmatter, not from charter's code. At 'advise' the existing commitment gate leads with the ROSTER — who exists, what each advertises (delegate-when), when each was last dispatched — and charter NEVER names which persona owns the prompt (ADR 0016: a keyword overlap between a request and a prose advert is not evidence of ownership, and the first confident wrong answer costs the block its reader). At 'require' the first Write/Edit of a turn where the roster fired and nothing was dispatched surfaces an ASK, never a deny; a dispatch clears it, which is also why sub-agents never see it. Separately, 'borrows:' now splits what 'uses:' overloaded: declare it and your auto-approved tools come from that list while 'uses:' becomes a routing edge; declare nothing and the legacy grant is unchanged; 'borrows: none' borrows nothing. Whether any of this works is measured by 'charter persona stats' → 'routing advice fired N · M dispatches followed'.
