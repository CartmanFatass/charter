Where charter's own conventions are WRITTEN DOWN, so they are cited rather than re-derived: docs/adr/ holds 16 ADRs and they are load-bearing, not history. The ones most often needed: 0008 (the plane root is NOT a work tree — work happens in workspaces/<ws>/<repo>, and a clone is its own git repo), 0009 (errors classify, they do not guess), 0011 (the record holds only what git cannot know — derive from git at read time rather than caching), 0012 (the plan is todos; the lifecycle belongs to the piece, and nothing closes a todo automatically because coverage is a judgement a program with no model cannot make), 0013 (report an age, never a verdict), and 0016 (charter presents the roster; it never guesses the owner). Also unwritten but enforced by review: additive-only (never delete or rename a user's file — name the blocker and do everything unblocked), fail toward no change (an unrecognised config value falls back to the behaviour that alters nothing), ONE source of truth (if two code paths answer the same question they must call the same function — most bugs found in this repo were a module global read where the file on disk was meant), hooks never break a turn, and comments record the WHY, usually the reason a previous more obvious approach failed. A proposal that contradicts a comment without addressing it is a proposal to reintroduce a fixed bug.
