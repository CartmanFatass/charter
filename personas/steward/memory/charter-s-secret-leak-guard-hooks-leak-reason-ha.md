_2026-08-18 16:51 · persistent_

charter's secret-leak guard (hooks._leak_reason) had a false-positive class worth remembering as a SHAPE, not a case: it fired whenever a program in _READERS (cat less head tail grep rg ag awk sed od xxd nl tac strings bat more) had ANY argument matching .charter/(vaults/|browser|active-) — including a heredoc BODY (shlex-split into argv by _segment_argv), a sed/awk script operand, or a grep PATTERN. So writing documentation that merely MENTIONS charter's own layout was denied as reading it. Fixed in PR #266 by (a) stripping heredoc bodies fed to a READER only (a body fed to bash/python is a script, and stripping it would hide commands from the guard) and (b) matching only real FILE OPERANDS, skipping the script/pattern operand of sed/awk/grep plus flag values. Gotcha found while doing it: the flag-takes-a-value table MUST be per tool — 'head -n 5' takes a count while 'sed -n' is quiet and takes nothing, so a shared list swallows sed's script operand and lets 'sed -n 1p .charter/active-persona' through, which is a real read. Still unmatched by design: a bare '.charter/vaults' with no trailing slash (the slash is what keeps .charter/vaults.json, the registry, an ordinary read).
